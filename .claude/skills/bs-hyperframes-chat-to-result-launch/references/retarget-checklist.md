# Retarget checklist

Every line must pass before Scene 1 is written. Paste the filled list into the handoff.

## 1. The host interface — the blocking gate

- [ ] It is established, in writing from the caller, whether the surrounding app is
      (a) an interface the caller owns, or (b) a neutral original built for this film.
- [ ] If (a): the tokens, iconography, and layout come from the caller's real product.
- [ ] If (b): no third-party wordmark, mark, icon set, menu structure, signature layout,
      or distinctive chrome appears anywhere, and the deliverable says in plain words that
      the surrounding app is representative rather than a specific product.
- [ ] No screen recording of a third-party app is used.
- [ ] The caller's own mark is the only logo in the film.

If this section cannot be completed, build the neutral original. A verbal assurance is not
enough to recreate someone else's interface in a film that will be published.

## 2. The product and the invocation

- [ ] The exact action a user takes to invoke the product is confirmed, and Scene 1 shows
      that action rather than an approximation of it.
- [ ] `product_row` is the product's real name as it would appear in a connector list.
- [ ] The film demonstrates one continuous flow. If the real product needs a setup step
      the film skips, that is stated in the handoff.

## 3. The script

- [ ] `question` reads like something a user would type, not like a setup line.
- [ ] `followup` names what the product does, once, plainly.
- [ ] `answer_prose` lines are real content worth reading, not marketing filler.
- [ ] The voiceover script is approved before any audio is generated, because re-timing
      the film to a new read is the single most expensive change in this workflow.

## 4. Audio is locked before picture

- [ ] The voiceover exists as a file.
- [ ] It has been transcribed to word-level timestamps.
- [ ] Every scene duration in `STORYBOARD.md` is derived from those timestamps.
- [ ] The music bed is licensed for the caller's intended distribution.
- [ ] Every `<audio>` element has an `id`.

## 5. The result is true

- [ ] Every `tasks` row is something the product actually runs, in the real order.
- [ ] `hero_stat` is a real number the caller will defend publicly.
- [ ] `hero_label` states what the number measures, unambiguously.
- [ ] If the number is soft, the count-up is cut rather than fudged.
- [ ] The output shown in the card is a real output of the product, or is clearly built
      from the caller's own material.

## 6. Palette and type

- [ ] The canvas is near-black, not `#000`.
- [ ] Three panel elevations are distinguishable at render resolution.
- [ ] The interface is greyscale, and the accent pair appears only in the product's mark
      and its progress details.
- [ ] The count-up uses tabular figures.
- [ ] Type licenses cover use in a rendered, distributed video.

## 7. Copy fits

- [ ] Every slot is inside its budget from `film-blueprint.md`.
- [ ] The count-up value renders legibly at 180px+ without wrapping.
- [ ] Menu rows are tall enough for cursor travel to read at 60fps.

## 8. Rights and honesty

- [ ] Nothing states or implies affiliation with, endorsement by, or authorization from
      any company the caller does not own.
- [ ] No real person's name, handle, avatar, or likeness appears.
- [ ] The caller owns or has licensed every supplied asset, and has said so.
